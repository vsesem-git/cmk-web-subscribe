# ЦМК — Вебинары для подписчиков (PHP)

Веб-приложение: список вебинаров с фильтрами, ролями (администратор/пользователь),
управлением пользователями, отправкой писем (доступ и приглашение) через SMTP.

## Структура

```
index.php               — главная страница (экран входа + приложение)
partials_modals.php     — HTML модальных окон
config.php              — конфигурация (СЕКРЕТЫ! замените APP_SECRET)
assets/
  app.css               — стили
  app.js                — клиентская логика (общается с /api)
api/
  index.php             — точка входа API (?action=...)
  users.php             — управление пользователями (только админ)
  settings.php          — настройки SMTP/источника (чтение — все, запись — админ)
  mail.php              — предпросмотр и отправка писем
lib/
  security.php          — заголовки, CSRF, сессии, роли, санитайзинг
  storage.php           — чтение/запись JSON с блокировками
  mailer.php            — отправка через PHPMailer (SMTP+TLS)
  email_templates.php   — генераторы HTML-писем
vendor/PHPMailer/       — библиотека PHPMailer (без composer)
data/                   — данные (НЕ доступны по HTTP)
  users.json            — пользователи (пароли в виде bcrypt-хешей)
  webinars.json         — список вебинаров
  settings.json         — SMTP и настройки отображения
```

## Требования
- PHP 7.4+ (проверено на 8.4). Рекомендуется расширение `mbstring` (есть fallback без него).
- Веб-сервер Apache (используются `.htaccess`) или Nginx (см. ниже).
- Каталог `data/` должен быть доступен PHP на запись.

## Установка
1. Скопируйте всю папку `php-project` на сервер (например, в корень сайта).
2. Откройте `config.php` и **замените `APP_SECRET`** на случайную строку 64+ символов.
3. Проверьте права: `chmod -R 750 .` и `chmod -R 770 data` (или как требует ваш хостинг).
4. Откройте сайт в браузере. Демо-вход администратора: **admin / admin123** — сразу смените!
5. В шестерёнке → вкладка «SMTP / Почта» укажите параметры вашего почтового сервера.

## Безопасность (что реализовано)
- **Пароли** хранятся только как bcrypt-хеши (`password_hash`), сверка `password_verify`.
- **CSRF-токен** обязателен для всех изменяющих запросов (POST/PUT/DELETE).
- **Сессии**: `HttpOnly`, `SameSite=Strict`, `Secure` под HTTPS, регенерация ID,
  привязка к User-Agent, защита от фиксации сессии.
- **Заголовки**: CSP, X-Frame-Options: DENY, X-Content-Type-Options, Referrer-Policy, HSTS (под HTTPS).
- **Rate-limit**: на вход (5/5 мин) и на отправку писем (20/10 мин).
- **Разделение прав**: управление пользователями и запись настроек — только админ.
- **SMTP-пароль** никогда не отдаётся в браузер (только флаг «задан»).
- **SMTP c проверкой сертификата** (`verify_peer`) — защита от MITM.
- **Данные** (`data/*.json`) закрыты от прямого HTTP через `.htaccess`.
- Весь вывод экранируется (`h()` на сервере, `esc()` на клиенте).

### Обязательно на боевом сервере
1. Замените `APP_SECRET` в `config.php`.
2. Включите **HTTPS** и раскомментируйте редирект в корневом `.htaccess`.
3. Смените пароль администратора и удалите демо-пользователей.
4. Убедитесь, что `data/`, `lib/`, `vendor/` недоступны по прямой ссылке
   (на Apache — через .htaccess; на Nginx — правилами location, см. ниже).

## Настройка Nginx (если не Apache)
`.htaccess` не работает в Nginx. Добавьте в конфиг сайта:
```nginx
location ~* /(data|lib|vendor)/ { deny all; return 404; }
location ~* /config\.php$ { deny all; return 404; }
location ~* \.(json|log|ini|bak|tmp)$ { deny all; return 404; }
```

## Ссылка на кабинет
В `config.php` параметр `CABINET_BASE` (по умолчанию `https://edu.vsesem.ru/webinar/`).
В письмах формируется ссылка вида `.../webinar/{id}`.

## Источник данных вебинаров
- Если в «Настройки → Источник данных» указан **URL** (например
  `https://edu.vsesem.ru/admin/data/webinars.json`) — список берётся оттуда.
  Данные кэшируются на сервере на `WEBINARS_CACHE_TTL` секунд (по умолчанию 30) —
  так обновление подхватывается при перезагрузке страницы, но без нагрузки на источник
  при каждом запросе. Кнопка **«Обновить»** в интерфейсе сбрасывает кэш и тянет свежее.
- Если URL пустой — используется локальный `data/webinars.json`.
- **Категория (направление)** определяется строго по полю `direction` в JSON
  (принимаются как ключи `zhkh/zdrav/energy/eco/build/goz`, так и русские названия
  «ЖКХ», «Здравоохранение» и т.п.). Неизвестное/пустое значение → «Прочее».
  Выбор направления для фильтра — через чипы над таблицей.

## Логирование и журналы
Логи пишутся в `data/logs/` в формате JSON Lines (одна запись на строку):
- **login.jsonl** — все попытки входа (успех/ошибка, IP, User-Agent, причина).
- **views.jsonl** — просмотры вебинаров (кто, какой вебинар, когда, IP). Фиксируется при клике «Смотреть»/«Запись».
- **mail.jsonl** — отправленные письма (кем, кому, тип, тема, результат/ошибка).

Кроме того, в `users.json` для каждого пользователя обновляются `last_login`, `last_ip`, `login_count`.

Админ видит всё это в шестерёнке → вкладка **«Журналы»**: сводка + таблицы (просмотры/входы/письма)
с экспортом в **CSV** (кнопка «Экспорт в CSV»). Напротив каждого пользователя — иконка «глаз»
для просмотра его личной истории (доказуемо: «смотрел / не смотрел»).

Пользователь видит свою историю сам — кнопка **«Мои просмотры»** в шапке (последний вход, кол-во входов,
список открытых вебинаров с числом открытий и датой последнего).

## Управление функциями (тумблеры)
Шестерёнка → вкладка **«Функции»** (только админ). Каждую возможность можно включить/выключить:
логирование входов / просмотров / писем, кнопки «Отправить доступ» и «Отправить приглашение»,
раздел «Мои просмотры», таймер обратного отсчёта, значок «просмотрен», предупреждение об окончании
подписки, блок «Прошедшие вебинары». Отключённые функции **скрываются у пользователей и не работают
на сервере** (например, при выключенном логировании записи не пишутся; отправка отключённого письма даёт 403).

## Авто-очистка логов
Шестерёнка → «Журналы» → блок «Авто‑очистка логов»:
- **Хранить не дольше N дней** и/или **не более N строк** на файл («0» = без ограничения).
- Очистка запускается **автоматически** при обращении к API, но не чаще **раза в сутки** (без cron —
  метка `data/logs/.last_prune`). Можно запустить вручную кнопкой **«Очистить сейчас»**.
- Кнопка **«Очистить этот лог»** полностью обнуляет выбранный журнал.

## Экспорт / импорт конфигурации
Шестерёнка → вкладка **«Конфигурация»** (только админ):
- **Экспорт** — скачивает один JSON-файл со всеми настройками (SMTP, функции, авто-очистка),
  пользователями и списком вебинаров. Пароли пользователей выгружаются **только в виде bcrypt-хешей**.
  Пароль SMTP по умолчанию **не включается** (есть галочка, если он всё же нужен для переноса).
- **Импорт** — загрузка ранее скачанного файла с выбором разделов (настройки / пользователи / вебинары).
  Защита: проверяется тип файла (`kind = cmk-config-bundle`); при импорте пользователей обязателен
  хотя бы один администратор; если в файле пустой пароль SMTP — текущий пароль сохраняется.
  Импорт заменяет выбранные данные — перед этим сделайте экспорт текущей конфигурации.

Формат файла: `{ kind, version, exported, settings, users, webinars }`. Удобно для резервных копий
и переноса на другой сервер/домен.

## Размер шрифта по столбцам
Шестерёнка → «Функции» → блок «Размер шрифта по столбцам (px)»: админ задаёт размер
для «Дата», «Лектор», «До начала», «Тема», «Цена» (10–28px). Значение общее для всех
пользователей (хранится в `settings.json`). Столбец «Тема» дополнительно **сам уменьшает
шрифт**, если текст не помещается по ширине ячейки (до 11px), и обрезает многоточием.

## Таймер обратного отсчёта
Таймер «До начала» считает до времени начала вебинара. Час начала по умолчанию задаётся
в «Настройки → Вид → Час начала вебинаров» (по умолчанию 10:00). Если у вебинара в JSON
есть поле `time` (напр. `"14:00"`) — используется оно. В день проведения показывает
«Идёт сейчас», после — «завершён». Часовой пояс сервера — Europe/Moscow.

## Внешний вид (вкладка «Вид» в настройках)
Всё применяется для всех пользователей (хранится в `settings.json`):
- **Пресеты** «Компактный / Обычный / Крупный» — задают размеры шрифта и плотность одним кликом.
- **Плотность строк** — компактно / обычно / просторно.
- **Тёмная тема** — переключатель (быстрый тумблер также в шапке).
- **Режим отображения** — таблица / карточки (быстрый тумблер в тулбаре).
- **Час начала вебинаров** — для таймера «До начала» (все начинаются в 10:00; можно переопределить полем `time`).
- **Пагинация** — «Показывать по N строк» (0 = все; иначе кнопка «Показать ещё»).
- **Формат даты** — шаблон `D MMMM YYYY` (D/DD/M/MM/MMMM/YYYY/YY).
- **Колонки** — порядок (drag-n-drop), видимость, переименование.
- **Сопоставление полей JSON** — какое поле внешнего файла идёт в какую колонку.
- **Цвета и подписи категорий** — переопределение через color-picker.
- **Размер шрифта по столбцам** (10–28px) и **ширина столбцов** (0 = авто) — живой предпросмотр;
  колонки также тянутся мышью за границу заголовка (как в Excel) с авто-сохранением.
- **Сброс к стандартным** одной кнопкой.

## Пользовательские пресеты фильтров
Панель под чипами направлений: сохранённые сочетания «период + направление + поиск».
Кнопка «+ пресет» сохраняет текущий фильтр, клик по пресету — применяет, «×» — удаляет (админ).

## Формат данных (вкладка «Формат JSON»)
Встроенная справка для того, кто редактирует внешний файл: описание всех полей вебинара
(`id, date, time, speaker, title, price, direction, link_participant`), допустимые значения
`direction` и готовый пример JSON с кнопкой «Скопировать».

## Data-driven архитектура
Колонки описаны реестром `COL_DEFS` в `assets/app.js` (у каждой `head()` и `cell()`), а их
порядок/видимость/подписи — данными в `settings.json → columns`. Чтобы добавить новую колонку,
достаточно добавить запись в реестр и в конфиг — без правки разметки. Формат внешних данных
приводится к каноническому через `settings.json → field_map`.

## Автоверсия ассетов (кэш без лишней нагрузки)
Ссылки на `assets/app.css` и `assets/app.js` формируются функцией `asset()` (config.php)
с параметром `?v=<filemtime>` — временем последнего изменения файла:
- Пока файл не менялся — версия та же, браузер берёт его из кэша (сервер не нагружается).
- Как только вы обновили файл — `filemtime` меняется, ссылка меняется, браузер сам подтягивает
  свежую версию. **Ctrl+F5 больше не нужен.**
- `filemtime` кэшируется в пределах запроса (static-переменная) — вызывается один раз на файл.
- В `assets/.htaccess` выставлен долгий кэш (`max-age=1 год, immutable`), что безопасно
  благодаря версионированию — статика грузится с диска браузера, а не с сервера.

## Проверка SMTP
Шестерёнка → «SMTP / Почта» → поле «отправить тестовое письмо на» + кнопка **«Проверить SMTP»**.
Отправляет тестовое письмо и показывает результат/ошибку соединения. Результат тоже пишется в mail.jsonl.

## Портируемость (любой домен / поддомен / подпапка)
Базовый путь определяется автоматически (`app_base_path()` в `config.php`), все ссылки на ресурсы и API —
относительные. Проект работает без правок кода при размещении в:
- `https://site.ru/` (корень),
- `https://sub.site.ru/` (поддомен),
- `https://site.ru/webinars/` (подпапка любой вложенности).

Единственное, что задаётся вручную — `CABINET_BASE` (домен вашего личного кабинета для ссылок в письмах).
